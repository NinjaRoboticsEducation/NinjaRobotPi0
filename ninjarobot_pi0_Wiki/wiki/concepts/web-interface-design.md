# Pi0 web interface design and compatibility

The current Pi0 interface uses Home (`/`) as the combined landing page/menu, Movement Tool (`/movement`) for distance and direct native controls, and Chat (`/agent`) for prompts and browser voice input. Hamburger links return Home; the removed Help route redirects there. Cyan-outlined dark cards, orange actions and the active/idle voice styles follow the six owner-supplied references. Backend/runtime/driver behavior, session ownership, native endpoint contracts and power confirmation are preserved. Earlier menu-sheet/combined-dashboard descriptions are historical.[^src-20261011-developmentguide] [^src-20261011-webrefinementevidence]

## Single-browser session ownership and reconnect screen (2026-10-10)

The shared application layout (`Layout.jsx`) maintains a persistent `/ws/session` WebSocket carrying a server-issued HttpOnly `ninja_web_session` cookie across Home, Movement Tool and Chat routes; current presentation retains that ownership hook.[^src-20261011-developmentguide][^src-20261010-lifecyclerefinementsimplementationplan] [^src-20261010-readme-2]
- **Session Exclusivity**: Exactly one browser controls web APIs; multiple tabs sharing the cookie act as one controller. Secondary connections receive a 4409 close code and a busy status message.[^src-20261010-lifecyclerefinementsevidence]
- **Endpoint Gating**: All `/api/` endpoints and auxiliary sockets (`/ws/distance`, `/ws/events`) require active session ownership (returning 423 if inactive, 503 during server shutdown).[^src-20261010-lifecyclerefinementsevidence]
- **Disconnect Cleanup**: Closing the browser or reaching a 35s timeout aborts ongoing native and Blockly tasks, cancels pending HTTP/greeting work, and restores the waiting QR code (ngrok URL or LAN URL) on the robot display.[^src-20261010-lifecyclerefinementsimplementationplan] [^src-20261010-lifecyclerefinementsvalidation]
- **Idle Suppression**: `RuntimePipeline` suppresses automatic idle face animation painting while waiting on the reconnect screen.[^src-20261010-lifecyclerefinementsimplementationplan]

## Browser Speech Recognition and Lifecycle Management (2026-10-11)

The Agent page provides browser-based voice input powered by the Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`). The browser speech service transcribes voice into text inside the chat input box and the user submits it as normal text messages to `/api/agent/chat`.[^src-20261010-shutdownvoicefixes]
* **Provider Independence**: Because recognition happens client-side before text transmission, microphone voice input is supported across all cloud AI providers (Google, OpenAI, Anthropic, Ollama Cloud) and does not require provider-level raw audio ingestion capabilities.[^src-20261010-shutdownvoicefixes] [^src-20261010-developmentguide-4]
* **Component Lifecycle**: The speech recognition instance is tied to the Agent page lifecycle, ensuring recording aborts immediately upon route navigation or component unmount.[^src-20261010-shutdownvoicefixes]

## Mobile Viewport Adaptation, Selection State, and Fullscreen (2026-10-11)

The mobile web interface refinement resolves short-screen and on-screen keyboard clipping through reactive viewport tracking and stateful UI adaptation:[^src-20261011-developmentguide-2] [^src-20261011-webmobilerefinement]
* **Visible Viewport Shell**: The `useAppViewport` hook subscribes to `window.visualViewport` resize and scroll events, dynamically locking whole-document scrolling (`overflow: hidden`) and allocating bounded remaining-height regions for chat messages, prompts, and system logs to prevent layout shifting during keyboard pan/resize.[^src-20261011-webmobilerefinement]
* **Responsive Layout & Short-Screen Fallbacks**: Replaces fixed vertical height deductions with CSS container allocations, landscape two-column wrapping, compact vertical breakpoints, and minimum 44px tap targets.[^src-20261011-webmobilerefinement]
* **Mutually Exclusive Interface Selection**: Home (`/`) presents Movement Tool and Chat entry buttons in dark-blue/cyan styling. Activating either route stores that selection in persistent `Layout` state for the session visit. Returning Home exclusively highlights the selected link in orange/white while restoring the other to dark blue; reloading the page resets both to the default base style.[^src-20261011-developmentguide-2] [^src-20261011-webmobilerefinement]
* **Synchronous Fullscreen Activation**: Interface entry buttons invoke standard and WebKit-prefixed Fullscreen APIs synchronously within the user activation gesture, remaining gracefully interactive when unsupported or denied.[^src-20261011-developmentguide-2] [^src-20261011-webmobilerefinement]
* **Header Robot Type Status**: Upon acquiring web session ownership, `Layout` retrieves validated HAL metadata via `GET /api/robot/status` and displays `NINJA ROBOT Pi0 - <localized type>` (`Tire`, `Humanoid`, or `Spider`) in the header across English, Japanese, Traditional Chinese, and Simplified Chinese, omitting the suffix on error without guessing.[^src-20261011-developmentguide-2] [^src-20261011-webmobilerefinement]
* **Browser Validation Matrix**: 612 automated assertions in `tests/browser_ui.cjs` across 9 screen dimensions (320×568 to 1280×900) validated viewport fit, control reachability, selection persistence, and fullscreen fallback; native WebKit/Safari, physical touchscreens, and hardware actuation remain pending owner acceptance.[^src-20261011-webmobilerefinement]

## Owner phone-test spacing correction and centered power label (2026-10-11)

Following native mobile browser testing on owner devices, spacing and slider geometry were corrected to eliminate compressed layouts under browser toolbars and center the power-off label:[^src-20261011-developmentguide-3] [^src-20261011-mobilespacingvalidation]
* **Named Size Container (`robot-page`)**: Layout establishes a `@container robot-page (min-width: 0px)` wrapping main content, ensuring Home and Movement evaluate available viewport space rather than global window dimensions that can be skewed by mobile chrome or on-screen keyboards.[^src-20261011-developmentguide-3] [^src-20261011-mobilespacingvalidation]
* **Card Distribution & Line Spacing**: Cards share remaining vertical height through flex allocation and explicit gap clamps (`clamp(12px, 2cqh, 22px)` normal, 10px compact below 620px/640px page height), preventing dead space below the final card. Card headings use 1.25 line-height, standard descriptions use 1.5, and compact descriptions use 1.45.[^src-20261011-developmentguide-3]
* **Two-Column Short-Landscape Home**: At container widths of at least 480px and heights up to 500px, Home reorganizes into two columns with Language and Power in the left column and Control Interface spanning both rows on the right, maintaining full slider track width.[^src-20261011-developmentguide-3]
* **Symmetric Centered Power Slider**: `PowerOffSlider` expands to a 64px track height with a 48px thumb and symmetric 54px left/right clearances, centering the label text on both axes within 1px. Label text uses container-query width sizing (`clamp(16px, 6.4cqw, 22px)`) at 1.25 line-height, ensuring legibility across all four locales.[^src-20261011-developmentguide-3] [^src-20261011-mobilespacingvalidation]
* **Movement Drawer Margin**: Movement Tool scrollport establishes an explicit bottom margin reserving clearance above the collapsed System Activity drawer, preventing long translated controls from slipping beneath the tab.[^src-20261011-developmentguide-3] [^src-20261011-mobilespacingvalidation]
* **Expanded Verification**: 813 assertions in `tests/browser_ui.cjs` across 11 screen sizes (including VisualViewport toolbar simulation at 390×670 and 390×740) and four languages validated no-overflow, minimum 10px gaps, description line heights >=1.4, and slider label centering; physical phone acceptance in Chrome and Safari remains pending retest.[^src-20261011-mobilespacingvalidation]

## Web gamepad and palette refinement (2026-10-13)

Following owner approval of `DevelopmentPlanDoc/NinjaRobotPi0WebRefinement_261013.md`, the web interface received targeted visual and interactive gamepad refinements:[^src-20261013-developmentguide-4] [^src-20261013-webgamepadvalidation]
* **Refined Palette and Contrast Tokens**: Home default interface navigation buttons and the header hamburger use medium blue fills. Selecting an interface applies an orange highlight that persists until the page is reloaded, resetting to medium blue.[^src-20261013-developmentguide-4] [^src-20261013-home-390x740] [^src-20261013-home-selected-390x740] The power slider features an orange thumb with a white icon and a centered blue track label.[^src-20261013-home-390x740] Idle Voice Input and the folded System Activity tab use blue/white, switching to orange/white during active recording and open activity drawers.[^src-20261013-developmentguide-4] [^src-20261013-chat-390x740] [^src-20261013-long-log-390x740] Content cards, panels, and colored chat messages use cyan borders at alpha 0.25 (75% transparency), while assistant messages retain gray borders at alpha 0.25.[^src-20261013-developmentguide-4] [^src-20261013-chat-390x740] Text, focus rings, and interactive outlines do not inherit reduced opacity.[^src-20261013-developmentguide-4]
* **Movement Tool Five-Button Gamepad**: The Movement Tool features an unboxed millimetre distance telemetry indicator at the top left of a centered five-button cross-shaped gamepad.[^src-20261013-webgamepadvalidation] [^src-20261013-movement-390x740] Explanatory paragraphs were removed from the three selector cards (Movements, Face Expressions, Sounds) for a streamlined interface.[^src-20261013-webgamepadvalidation] [^src-20261013-movement-390x740] In short landscape viewports, the pad sits beside the selector column, maintaining internal scrollability without document-level overflow.[^src-20261013-webgamepadvalidation] [^src-20261013-movement-568x320] [^src-20261013-movement-enlarged-ja-390x740]
* **Directional Hold Loop and Finish-Current-Cycle Release**: Directional buttons (`run_forward`, `run_backward`, `turn_left`, `turn_right`) issue one POST request at a time to `/api/servos/movements/run`, awaiting exact executed completion before repeating.[^src-20261013-webgamepadvalidation] Releasing the button cancels repetition and immediately clears orange styling, while allowing the in-flight cycle to finish its complete trajectory.[^src-20261013-webgamepadvalidation] [^src-20261013-gamepad-pressed] Home triggers a single execution and stays orange until release; assistive clicks trigger one cycle.[^src-20261013-webgamepadvalidation]
* **Hardware & Type Scoping**: Supported Spider and Humanoid robots map to advertised native movements (`run_forward`, `run_backward`, `turn_left`, `turn_right`, `home`). On Tire or unsupported robot profiles, directional buttons are cleanly disabled with localized explanatory tooltips.[^src-20261013-developmentguide-4] [^src-20261013-webgamepadvalidation]
* **Safety Guards and Unknown-Status Latch**: Pointer capture loss, keyboard autorepeat rejection, window blur, visibility change, and route navigation invalidate hold intent.[^src-20261013-webgamepadvalidation] An HTTP 4xx error halts repetition and allows re-pressing. An HTTP 5xx, network error, or unconfirmed completion latches an unknown-status lock across routes, requiring the operator to inspect the robot before reloading the browser.[^src-20261013-webgamepadvalidation] Browser reload clears the frontend latch without providing a hardware stop guarantee.[^src-20261013-webgamepadvalidation]
