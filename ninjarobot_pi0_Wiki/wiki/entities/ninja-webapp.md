# ninja_webapp Package

## Current interface and contracts

`ninja_webapp` is the existing React 19.2/Vite SPA with four locale bundles (`en`, `ja`, `zh-TW`, `zh-CN`). The owner-requested refinement changes frontend presentation only; backend/driver APIs, robot configuration, session ownership and shutdown confirmation remain unchanged. BLE advertising is distinct from web controller ownership.[^src-20261011-developmentguide] [^src-20261011-readme-current] [^src-20261011-readme-final] Earlier foundational contracts originate in the initial repository design.[^src-20260822-developmentguide] [^src-20260822-readme]

## Application pages

- **Home (`/`)** combines language, interface selection and confirmed System Power. It is also the hamburger-menu destination.
- **Movement Tool (`/movement`)** contains live distance and server-supplied native movement, face and sound selectors. Execution uses the existing direct POST endpoints and does not call Ninja Agent.
- **Chat (`/agent`)** contains conversation/local clear, a prompt/send row and browser voice transcription into the prompt. It keeps the existing `{message, language}` chat payload and aborts recognition on navigation.
- **Legacy Help (`/help`)** redirects Home; the Help implementation is removed. Unknown frontend routes also return Home.[^src-20261011-developmentguide] [^src-20261011-readme-current]

Movement and Chat share a bottom System Activity drawer, folded by default and expanded above content with timestamp/message rows, local clear and independent scrolling. `/ws/distance` remains a separate millimetre stream; `/ws/events` supplies actual runtime activity. The header badge uses real `/ws/session` ownership, not BLE advertising. Mobile-first columns, bounded widths, wrapping forms/messages, safe areas and localized/document-language labels implement the supplied design.[^src-20261011-developmentguide] [^src-20261011-webrefinementevidence]

Frontend lint/build, locale completeness, inert session/stream checks and protected-core verification passed. Browser validation was explicitly waived on the Pi Lite host; responsive/browser/device acceptance remains manual and is not implied by source checks.[^src-20261011-webrefinementevidence]

## Shared session lifecycle and reconnect management (2026-10-10)

`ninja_webapp` integrates session management in the shared application layout (`Layout.jsx`) using the `useRobotSession.js` hook.[^src-20261010-lifecyclerefinementsimplementationplan] A persistent `/ws/session` socket connects when the app mounts, carrying the server's HttpOnly session cookie across routes, now Home, Movement Tool and Chat.[^src-20261011-developmentguide] Heartbeat pings run every 10 seconds, with automatic retry every 3 seconds if disconnected. If a secondary browser attempts to connect while a session is active, the server closes the socket with code 4409, and the web app presents a busy status message preventing unauthorized control. The four locale bundles (`en`, `ja`, `zh-cn`, `zh-tw`) provide localized notifications for busy and reconnecting states.[^src-20261010-lifecyclerefinementsvalidation]

## Web Microphone Input and Voice Gating Correction (2026-10-11)

The Agent page microphone control uses client-side browser speech recognition (`SpeechRecognition` / `webkitSpeechRecognition`) to transcribe user voice input into the prompt text area, sending the transcribed text via `/api/agent/chat` when submitted.[^src-20261010-shutdownvoicefixes]

The `supports_audio` flag describes direct raw-audio processing at `/api/agent/voice`. Removing that gate from the UI microphone button restores voice typing for all providers regardless of model audio support.[^src-20261010-shutdownvoicefixes] [^src-20261010-developmentguide-4]
* **Lifecycle & Navigation Cleanup**: The Agent page manages its own recognition instance, resets recording state on startup errors, and cleanly aborts active speech recognition when unmounting during navigation.[^src-20261010-shutdownvoicefixes]

## Mobile Viewport Hooks, Layout State, and Status Integration (2026-10-11)

Enforces document-level scroll locking (`document.body.style.overflow = 'hidden'`) while preserving internal component scrolling.[^src-20261011-webmobilerefinement]
* **Cross-Browser Fullscreen (`fullscreen.js`)**: Encapsulates standard `requestFullscreen` and WebKit-prefixed API methods to trigger fullscreen mode during user touch/click events on interface selection cards.[^src-20261011-webmobilerefinement]

## Web Gamepad and Palette Refinement Architecture (2026-10-13)

The 2026-10-13 web refinement introduced dedicated interactive gamepad infrastructure and updated palette tokens while preserving all existing backend APIs and driver abstractions:[^src-20261013-developmentguide-4] [^src-20261013-webgamepadvalidation]
* **Gamepad Component (`components/common/GamePad.jsx`, `GamePad.module.css`)**: Implements a cross-shaped five-button control pad (Up, Down, Left, Right, Center Home) with unboxed upper-left millimetre distance readout.[^src-20261013-webgamepadvalidation] Uses `@container` sizing for dynamic landscape arrangement (positioning the pad beside movement selector cards on wide viewports) and compact vertical bounds.[^src-20261013-webgamepadvalidation] Buttons for Tire profiles or unadvertised actions are rendered in disabled state with localized guidance.[^src-20261013-webgamepadvalidation]
* **Interactive Hold Hook (`hooks/useGamePad.js`)**: Encapsulates pointer and keyboard events with pointer capture. Directional holding triggers sequential POST execution awaiting complete response before dispatching the next cycle.[^src-20261013-webgamepadvalidation] Releasing the button immediately cancels repetition and clears active styling while allowing the in-flight cycle to complete cleanly.[^src-20261013-webgamepadvalidation] Rejects synthetic keyboard repeat events and invalidates hold intent on window blur, visibility change, or component unmount.[^src-20261013-webgamepadvalidation]
* **Shared Request Lock and Error Latching (`utils/nativeMovement.js`)**: Coordinates command execution between the gamepad and selector cards, persisting a request lock across route navigation to prevent conflicting physical commands.[^src-20261013-webgamepadvalidation] If an execution request encounters a 5xx server error, network timeout, or ambiguous completion, it engages an unknown-status latch across all routes requiring physical robot verification before reloading.[^src-20261013-webgamepadvalidation]
* **System Activity Release Integration (`SystemActivity.jsx`)**: When the folded System Activity drawer is opened, it fires a release callback to cleanly cancel any active gamepad hold state.[^src-20261013-webgamepadvalidation]
* **Layout Context & Locale Bundles**: `Layout.jsx` injects the active `robotType` into the Outlet context. All four locale bundles (`en`, `ja`, `zh-TW`, `zh-CN`) supply identical localized strings for gamepad actions, disabled notices, and safety alerts.[^src-20261013-developmentguide-4] [^src-20261013-webgamepadvalidation]
